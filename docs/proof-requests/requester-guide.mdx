# Requester Guide

As the requester, you create the Proof Request, share the code with the respondent, and receive the risk assessment result. You never receive the raw evidence.

## Creating a Proof Request

<Steps>
  <Step title="Open the Requests tab">
    Tap the **Requests** tab at the bottom of the screen.
  </Step>

  <Step title="Tap Create Request">
    Tap the **Create Request** button (or the + icon in the top right).
  </Step>

  <Step title="Set the purpose and challenge">
    Enter a clear description of what you are asking the respondent to submit and why.

    **Good challenge examples:**
    - "Please submit the invoice you received from the vendor so I can assess whether it shows signs of manipulation."
    - "Please submit the message you received claiming to be from our IT department."
    - "Please submit the URL you want me to visit before I click it."

    Be specific. The respondent will read this challenge before submitting their evidence.
  </Step>

  <Step title="Set the expiry">
    Choose how long the request stays open:
    - **24 hours** — for urgent situations
    - **48 hours** — standard
    - **7 days** — when the respondent may need time to respond

    After expiry, the request closes and the respondent can no longer submit evidence. See [Expiration and Status](/proof-requests/expiration-and-status) for details.
  </Step>

  <Step title="Create the request">
    Tap **Create Request**. A 6-digit code is generated.
  </Step>

  <Step title="Share the code">
    Share the 6-digit code with the respondent through any channel — message, email, phone call, or in person.

    You can also share the direct link, which opens InvisiProof with the code pre-filled.

    <Note>
    The code is not secret — it only allows someone to submit evidence to this specific request. It does not grant access to your account or any other data.
    </Note>
  </Step>

  <Step title="Wait for the response">
    The request status changes as the respondent acts:
    - **Pending** — waiting for the respondent to submit evidence
    - **Submitted** — evidence received, analysis queued
    - **Analyzing** — AI analysis in progress
    - **Completed** — result ready

    You will see the status update in the Requests tab. You can also enable notifications to be alerted when the result is ready.
  </Step>

  <Step title="View the result">
    When the status is **Completed**, tap the request to view the risk assessment result.

    You will see:
    - Risk level and score
    - Summary of observable signals
    - Warning indicators
    - Recommended actions
    - Trust level

    You will **not** see the raw evidence submitted by the respondent.
  </Step>
</Steps>

## What you can and cannot see

| You CAN see | You CANNOT see |
|-------------|----------------|
| Risk level (Low/Medium/High/Critical) | The image, text, or URL submitted |
| Risk score (0–100) | The respondent's personal information |
| Warning indicators | The raw AI prompt or response |
| Recommended actions | Any other requests the respondent has responded to |
| Trust level | |
| Request status | |

This boundary is enforced at the database level and cannot be bypassed through the API.

## Managing your requests

- **View all requests** — the Requests tab shows all your active and completed requests
- **Delete a request** — tap the request and select Delete. This removes the request and all associated data, including the evidence (if submitted)
- **Expired requests** — expired requests are shown with an Expired status. You cannot reopen an expired request, but you can create a new one

## Tips for effective Proof Requests

- **Be specific in your challenge** — vague challenges lead to vague evidence submissions
- **Set an appropriate expiry** — don't set 24 hours if the respondent is in a different time zone
- **Follow up** — if the request expires without a response, you can create a new one
- **Interpret results in context** — a Low Risk result on a submitted document means the observable signals don't indicate manipulation, not that the document is definitely authentic
