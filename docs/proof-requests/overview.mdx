# Proof Requests

A Proof Request is a two-party workflow that lets you ask someone to submit evidence privately. You receive only the risk assessment result — not automatically the raw evidence they submitted.

## Why Proof Requests exist

Ordinary "send me a screenshot" verification creates a problem: the evidence may contain information the other person should not have to reveal. A Proof Request separates the evidence from the result.

**Example**: You want to verify a claim someone is making. You create a Proof Request. They submit the supporting evidence privately. InvisiProof assesses it. You receive the risk assessment — not their private documents, messages, or images.

## How it works

<Steps>
  <Step title="You create a request">
    Tap the Requests tab and create a new Proof Request. Set the purpose and any instructions for the respondent.
  </Step>
  <Step title="You share the code or link">
    InvisiProof generates a unique code and shareable link. Send it to the person you want to submit evidence.
  </Step>
  <Step title="They submit privately">
    The respondent opens the link, reviews the consent notice, and submits their evidence. They control what they submit.
  </Step>
  <Step title="InvisiProof assesses the evidence">
    The submitted content is analyzed for risk signals using the same process as direct assessments.
  </Step>
  <Step title="You receive the result">
    You see the risk assessment result in your Requests tab. You do not automatically receive the raw evidence.
  </Step>
</Steps>

## Key privacy boundaries

- Requesters cannot read the raw evidence submitted by respondents
- Respondents can delete their submission at any time
- The request expires if not completed within the set timeframe

See [Privacy Boundaries](/proof-requests/privacy-boundaries) for full details.
