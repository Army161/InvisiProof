# Proof Requests

A Proof Request is a structured two-party workflow that lets you ask someone to submit evidence privately. You receive only the AI-generated risk assessment result — never the raw evidence itself.

## Why Proof Requests exist

Sometimes you need to evaluate content that someone else holds. You might want to:
- Verify a claim someone is making about a document they possess
- Check whether an image someone sent you has been manipulated
- Evaluate a message or URL that a third party wants you to act on
- Ask a potential business partner to submit credentials for risk assessment

The challenge: if you ask them to send you the evidence directly, you receive the raw content — which may be sensitive, may be manipulated, or may expose you to liability. Proof Requests solve this by keeping the evidence private while still giving you a risk assessment.

## The two-party workflow

```
Requester                              Respondent
    │                                      │
    │  1. Create Request                   │
    │     (set purpose + expiry)           │
    │                                      │
    │  2. Share 6-digit code ──────────────►│
    │                                      │
    │                          3. Enter code in app
    │                          4. Read the challenge
    │                          5. Submit evidence
    │                             (image/text/URL)
    │                                      │
    │  6. Receive risk result ◄────────────│
    │     (NOT the raw evidence)           │
```

## What the requester sees

The requester receives:
- Risk level (Low, Medium, High, Critical)
- Risk score (0–100)
- Summary of observable signals
- Warning indicators
- Recommended actions
- Trust level

The requester does **not** receive:
- The raw image, text, or URL submitted by the respondent
- Any personal information about the respondent beyond what they chose to share
- The ability to download or view the evidence

## What the respondent sees

The respondent sees:
- The purpose/challenge set by the requester
- Confirmation that their evidence was submitted
- A privacy notice explaining that the requester cannot read their evidence

The respondent does **not** see:
- The risk assessment result (only the requester sees this)
- Any information about the requester beyond the challenge text

## Privacy enforcement

The privacy boundary between requester and respondent is enforced at the database level using Supabase Row Level Security (RLS) policies. The API cannot return evidence to the requester regardless of what the client requests. See [Privacy Boundaries](/proof-requests/privacy-boundaries) for technical details.
