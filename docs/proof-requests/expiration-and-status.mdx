# Expiration and Status

Every Proof Request has a status that reflects where it is in the workflow, and an expiry time after which the respondent can no longer submit evidence.

## Request statuses

<AccordionGroup>
  <Accordion title="Pending">
    **What it means:** The request has been created and the code has been generated, but the respondent has not yet submitted evidence.

    **What you can do:** Share the code with the respondent. Wait for them to submit. The request will remain in Pending status until the respondent submits or the request expires.

    **How long it lasts:** Until the respondent submits evidence or the request expires.
  </Accordion>

  <Accordion title="Submitted">
    **What it means:** The respondent has submitted their evidence. The evidence has been received and stored. Analysis has been queued but has not yet started.

    **What you can do:** Wait. Analysis typically begins within seconds of submission.

    **How long it lasts:** Usually a few seconds before transitioning to Analyzing.
  </Accordion>

  <Accordion title="Analyzing">
    **What it means:** The AI analysis is in progress. The evidence is being evaluated and the risk assessment is being generated.

    **What you can do:** Wait. Analysis typically completes within 10–30 seconds.

    **How long it lasts:** Usually 10–30 seconds. If a request stays in Analyzing for more than 5 minutes, see [Troubleshooting](/help/troubleshooting).
  </Accordion>

  <Accordion title="Completed">
    **What it means:** Analysis is complete. The risk assessment result is available for the requester to view.

    **What you can do:** Tap the request to view the full result including risk level, score, warning indicators, and recommended actions.

    **How long it lasts:** Indefinitely, until the request is deleted or the history retention period expires.
  </Accordion>

  <Accordion title="Expired">
    **What it means:** The request reached its expiry time before the respondent submitted evidence. The request is now closed.

    **What you can do:** Create a new Proof Request with a new code and share it with the respondent again.

    **How long it lasts:** Expired requests remain visible in your history until you delete them.
  </Accordion>
</AccordionGroup>

## Expiry options

When creating a Proof Request, you choose how long it stays open:

| Option | Best for |
|--------|----------|
| 24 hours | Urgent situations where you need a quick response |
| 48 hours | Standard requests with a reasonable response window |
| 7 days | When the respondent may need time to gather evidence or is in a different time zone |

<Note>
Choose the shortest expiry that gives the respondent enough time to respond. Shorter expiry windows reduce the risk of the code being used by an unintended recipient.
</Note>

## What happens when a request expires

When a Proof Request expires:

1. The status changes to **Expired**
2. The 6-digit code becomes invalid — the respondent can no longer use it to submit evidence
3. No evidence was submitted, so there is no risk assessment result
4. The expired request remains in your history until you delete it
5. You can create a new request with a new code if you still need the assessment

## What happens to submitted evidence after completion

Once a request reaches **Completed** status:

- The evidence remains stored in Supabase Storage, scoped to the proof request
- The requester still cannot read the evidence — the RLS policy remains in effect
- The evidence is retained according to your plan's history retention policy
- You (the requester) can delete the request at any time, which also deletes the evidence
- The respondent can request deletion by contacting support@invisiproof.com

## Notifications

You can enable push notifications to be alerted when a Proof Request you created reaches **Completed** status. Configure notifications in Profile → Notification Preferences.
