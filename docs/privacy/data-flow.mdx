# Data Flow

This page describes exactly what data leaves your device for each type of scan, where it goes, and what stays private.

## Image analysis

```
Your Device
    │
    │  1. Image file (JPEG/PNG/HEIC/WebP)
    │     Transmitted over HTTPS
    ▼
Supabase Storage (private bucket)
    │
    │  2. Edge function reads image from storage
    │     Image bytes sent to AI provider
    ▼
AI Provider (OpenAI / Anthropic / Google Gemini)
    │
    │  3. Structured analysis result returned
    ▼
Supabase Database (your account, RLS-protected)
    │
    │  4. Normalized result returned to app
    ▼
Your Device (result displayed)
```

**What leaves your device:** The image file, transmitted over HTTPS to Supabase Storage.

**What goes to the AI provider:** The image bytes (or a base64 representation), along with a structured analysis prompt. Your user ID, name, and account information are not sent to the AI provider.

**What stays on your device:** Nothing — the image is uploaded to Supabase. If you want to keep the image private, delete it from your scan history after reviewing the result.

**What is stored:** The image in Supabase Storage (private bucket, RLS-protected), the analysis result in the Supabase database (RLS-protected).

## Text analysis

```
Your Device
    │
    │  1. Text content
    │     Transmitted over HTTPS
    ▼
Supabase Database (encrypted column, RLS-protected)
    │
    │  2. Edge function reads text
    │     Text sent to AI provider
    ▼
AI Provider (OpenAI / Anthropic / Google Gemini)
    │
    │  3. Structured analysis result returned
    ▼
Supabase Database (your account, RLS-protected)
    │
    │  4. Normalized result returned to app
    ▼
Your Device (result displayed)
```

**What leaves your device:** The text content, transmitted over HTTPS to Supabase.

**What goes to the AI provider:** The text content and a structured analysis prompt. Your user ID and account information are not sent to the AI provider.

**What is stored:** The text content in the Supabase database (encrypted column, RLS-protected), the analysis result in the Supabase database (RLS-protected).

## URL analysis

```
Your Device
    │
    │  1. URL string
    │     Transmitted over HTTPS
    ▼
Supabase Database (RLS-protected)
    │
    │  2. Edge function reads URL
    │     URL string sent to AI provider
    │     (URL is NOT visited/fetched)
    ▼
AI Provider (structural analysis only)
    │
    │  3. Structured analysis result returned
    ▼
Supabase Database (your account, RLS-protected)
    │
    │  4. Normalized result returned to app
    ▼
Your Device (result displayed)
```

**What leaves your device:** The URL string, transmitted over HTTPS to Supabase.

**What goes to the AI provider:** The URL string and a structured analysis prompt. The URL is analyzed structurally — it is not visited or fetched.

**What does NOT happen:** Your device's IP address is never sent to the URL's destination server. The URL is never visited from InvisiProof's servers either.

**What is stored:** The URL string in the Supabase database (RLS-protected), the analysis result in the Supabase database (RLS-protected).

## Proof Request evidence

```
Respondent's Device
    │
    │  1. Evidence (image/text/URL)
    │     Transmitted over HTTPS
    ▼
Supabase Storage / Database
    │  (RLS: respondent_user_id only)
    │
    │  2. Edge function reads evidence
    │     Evidence sent to AI provider
    ▼
AI Provider
    │
    │  3. Structured analysis result returned
    ▼
Supabase Database
    │  Result: RLS: requester_user_id only
    │  Evidence: RLS: respondent_user_id only
    │
    │  4. Result returned to requester
    │     Evidence NOT returned to requester
    ▼
Requester's Device (result only)
```

**What the requester's device receives:** The risk assessment result only. The evidence never reaches the requester's device.

**What the respondent's device sends:** The evidence, transmitted over HTTPS to Supabase.

## Analytics data flow

```
Your Device
    │
    │  Event name + properties (no content)
    │  e.g. { event: "scan_completed", risk_level: "medium" }
    ▼
PostHog (privacy-conscious analytics)
```

**What is sent to PostHog:** Event names and non-sensitive properties (risk level, scan type, feature used). Image contents, text contents, URLs, and API keys are never sent to PostHog. See [Analytics](/privacy/analytics) for the full list of tracked events.

## BYOK data flow

When you have configured a BYOK (Bring Your Own Key) provider:

```
Supabase Edge Function
    │
    │  1. Fetches your encrypted API key from Supabase
    │  2. Decrypts key in the edge function
    │  3. Sends content + key to your provider
    ▼
Your AI Provider (OpenAI / Anthropic / Google Gemini)
```

**Your API key never leaves Supabase's server infrastructure.** It is decrypted in the edge function and used directly — it is not sent to InvisiProof's application servers or logged anywhere.
